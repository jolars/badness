# LSP & Environment Awareness

The formatter is hermetic: its output is a function of the input plus shipped
data. The language server is allowed more latitude, because navigation is
inherently about the local environment. A runtime query of the TeX distribution
feeding the formatter stays a non-goal; a read-only index or metadata feeding
LSP navigation is sanctioned.

## Why `lsp-server`, not `tower-lsp`

The LSP is built on `lsp-server` and `lsp-types`, rust-analyzer's stack. Salsa
cancellation is a synchronous unwind (`salsa::Cancelled`) that composes with
`lsp-server`'s sync main loop plus threadpool and fights tower-lsp's async
`&self` model. `text/line_index.rs` uses `lsp_types::Position`.

## Environment awareness

Three sources, all reading static facts only. No macro meaning, no typesetting.

### Shipped CTAN metadata

`crates/badness-parser/data/package_metadata.json`, generated by
`scripts/gen_package_names.py` from the pinned tlpdb, maps a package stem to a
description and catalogue id. It has the same read-only posture as the name
lists and CWL, and drives package hover and completion detail. The hover's link
row pairs a texdoc link, keyed on the TeX package name, with the CTAN catalogue
page, keyed on the catalogue id.

### A read-only TEXMF file index

`project::texmf` indexes the installed `.sty`, `.cls`, and `.dtx` files. Root
discovery is delegated to `kpsewhich -var-value`, since reimplementing
kpathsea's `texmf.cnf` resolution is out of scope and MiKTeX does not use it,
and enumeration goes through `ls-R` or a walk. The index is cached to the OS
cache directory keyed by a distro fingerprint, as a lazy process global where
the first config wins. It powers document links, go-to-definition, and
installed-set completion for system packages.

It is gated by the `texmf` editor settings (`enabled`, `roots`, `useKpsewhich`),
supplied as `initializationOptions` or through `didChangeConfiguration`. These
are machine config, so they live in the editor rather than in `badness.toml`.
The index is never wired into `scope_signatures` or `DiskPackageSource`, and a
test guards that.

### The compile's `.aux` artifacts

`project::aux` is a dedicated line-oriented scanner, never the LaTeX parser: aux
files are written under `\makeatletter`, so `\@input` and `\@writefile` would
mis-lex. It extracts `\newlabel` numbers and `\@writefile{toc}` entries,
following `\@input` per-chapter chains. Freshness is a per-file cache keyed by
mtime and length, so a recompile is picked up on the next request with no
watcher. Aux files are located per label namespace, either as a sibling `.aux`
or under `[build] aux-dir` for out-of-tree builds; latexmkrc and Tectonic
auto-detection are deferred.

This powers label hover (`Figure 3: A chart`) and document-symbol number
enrichment (`1.2 Intro`), with toc titles matched whitespace-normalized and
consumed in document order. A test guards that the formatter never reads the aux
file.

## Citation completion filtering

A `\cite{…}` completion returns the entire bibliography namespace, deduped by
folded key with the first definer winning. It is not prefix-filtered
server-side. Each item carries a `filterText` of key, title, and authors,
space-joined with the key first and capped at 128 characters, so the client
matches on any of those fields.

This is deliberately editor-agnostic. `filterText` is LSP-standard, so every
compliant client filters and scores against it and falls back to `label`, and
the behavior needs no client-specific code. The only thing that would have
blocked a title-word match is a server-side key filter, which we do not do.
`sortText` is the lowercased key, a deterministic tiebreak inside the client's
match-score bucket. The list keeps `isIncomplete: true`, so the client
re-queries as the prefix narrows.

The title and author strings are cached on the salsa-tracked bib semantic entry,
so building the list stays a per-keystroke walk over entries with no CST
descent.
